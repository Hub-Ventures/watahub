# Design System: watahub.dev

## Overview

**Creative North Star: "The Quiet Console, read aloud"**

watahub.dev is the account panel's world turned into a long reading page. It invents no new identity. The
authority for colors, radii, the type stack, the shared primitives (buttons, badges, the secret box, the segmented
control, rows, the checklist mark, icons, focus) and the named rules **One Teal, Word-and-Icon, Machine Mono,
Sentence Case and Overlays-Only** is
[`watahub-ee/DESIGN.md`](https://github.com/Hub-Ventures/watahub-ee/blob/main/DESIGN.md) with its sidecar
[`watahub-ee/.impeccable/design.json`](https://github.com/Hub-Ventures/watahub-ee/blob/main/.impeccable/design.json). This file
records only what the public site adds or adapts, measured from `site/public/site.css` and the six pages.

The site's own idea is that every WhatsApp moment sits beside its machine twin. On the left is what a person sees (a
chat well, a checklist, a list). On the right is what the machine gets or sends (the signed delivery, the
`POST /v1/messages` with no Meta token, the connect response). A thin connector joins the two. Display type is
larger than the panel's because the page has to persuade, but the density, borders, flatness and the single teal stay
at product level. The page is static: no scripts, no inline styles, every asset from `'self'`.

**Key Characteristics:**
- Inherits `tokens.css` and `components.css` verbatim from watahub-ee; `site.css` is the only stylesheet authored here.
- A display ramp the panel lacks (h1 up to 56px) over a 15px body, in a 1200px column.
- The hero h1 is the tagline alone, followed by the lede and three numbered steps in neutral circles.
- Message/record pairs as the recurring form: chat well on `bg`, record on `surface`, connector between.
- One authored motion: the hero connectors draw in once on load, cut by reduced motion.
- Every demo frame and sample value is labelled "Example data" in the page's language.
- Three languages with identical markup; light and dark follow the OS through the inherited `light-dark()` tokens.

### Mirrors and sync

`site/public/tokens.css` and `site/public/components.css` are byte-identical copies of watahub-ee
`public/tokens.css` and `public/components.css` at commit `a858f6b`, preceded only by a two-line header naming the
source and commit. `.prettierignore` excludes both so formatting never drifts them. A token or primitive change is
made in watahub-ee, then the two files are copied again with the header's commit updated. They are never edited
here, and `site.css` never redefines a token they declare.

## Colors

The palette is the panel's, unchanged: zinc neutrals, one teal, semantic green. The frontmatter lists only the tokens
the site uses, with the values inherited from watahub-ee; the site adds no color.

### Primary
- **Deep Teal / Bright Teal** (`accent`): the primary button ("Source on GitHub", the 404's home link), outbound
  bubbles, quick-reply prompt, the unread dot, connectors and code-well borders when a pair is lit, focus.
- **Teal Wash** (`accent-soft`): only the accent badge ("No Meta token") and the Secret box fill. Never inside a code
  well.
- **Teal Ink** (`accent-ink`): links, the accent badge label, quick-reply text.

### Neutral
- **Paper / Night** (`bg`): the page and the message side of every pair (the chat well).
- **Surface** (`surface`): the record side, frames, the values strip, rows, the hosted block, the closing band, the
  translucent top bar (86% mixed with transparent, 12px blur).
- **Surface 2** (`surface-2`): code wells (on every viewport), the language track, neutral badges, nav hover.
- **Surface 3** (`surface-3`): avatars and the hero step numbers.
- **Border / Border Strong** (`border`, `border-strong`): 1px frames and dividers / connectors at rest and the
  scrollbar thumb.
- **Ink, Ink 2, Ink 3** (`text`, `text-2`, `text-3`): body and step titles / ledes, step text and descriptions / meta, code
  keys, value labels, footer.

### Semantic
- **ok** (`ok`, `ok-soft`): check badges ("signed", "200") and the checklist marks. warn, err and info exist in the
  mirrored tokens but the site does not use them.

### Named Rules
**The Lit Pair Rule.** Teal appears on a connector or a code-well border only while its pair is hovered or focused.
At rest connectors are `border-strong` and code wells are borderless `surface-2`.

## Typography

**UI Font:** the system UI stack (inherited `--font`)
**Mono Font:** JetBrains Mono 400/500, self-hosted woff2 (inherited `--mono`); the 400 file is preloaded

**Character:** the operating system's own sans at a persuading size; mono marks every machine value, as in the panel.

### Hierarchy
- **Display** (600, `clamp(36px…56px)`, 1.1, -0.02em): the hero h1 only, set in `text`: the tagline as one statement,
  which wraps to two lines at 1440px.
- **Headline close** (600, `clamp(28px…40px)`, 1.15): the closing band's h2.
- **Headline miss** (600, `clamp(28px…44px)`, 1.15): the 404 h1.
- **Headline** (600, `clamp(24px…32px)`, 1.2): section h2s.
- **Lede** (400, `clamp(16px…18px)`, 1.55, max 48ch): the hero deck, the closing paragraph, the 404 text.
- **Deck** (400, 16px, 1.55, max 62ch): the paragraph under a section h2.
- **Title** (600, 15px): h3 inside rows lists and the block title of each hero step.
- **Body** (400, 15px, 1.5): the page default, one step above the panel's 14px for reading.
- **Step** (400, 14px, 1.5): hero step text, in `text-2`.
- **Numeral** (600, 12px, tabular): the hero step numbers.
- **Body md** (14px): bubbles, row descriptions, checklist, features and prose inside frames.
- **Body sm** (13px): frame heads, record notes, value descriptions, nav links, footer.
- **Label** (500, 12px): badges, value labels, record heads, language options.
- **Caption** (11px): bubble time meta only.
- **Code** (mono 12px, 1.55, ligatures off): every code well. **Code ticket** (mono 13px) is the closing response.

### Named Rules
**The Display Exception Rule.** Display sizes and the -0.02em tracking exist only on the h1 and the two oversized
headings above; everything else stays on the inherited panel scale. Sentence Case still holds: no uppercase, no
tracked labels.

## Layout

- **Column:** `.wrap` is `min(1200px, 100% - 2 × gutter)`, gutter `clamp(16px, 4vw, 40px)`, centered.
- **Top bar:** sticky, 56px, one row on desktop: logo and name, section links (left, `margin-right:auto`), the
  language control, a small GitHub button. Anchors land 16px below it (`scroll-padding-top`).
- **Hero:** padding `clamp(32px…48px)` top and `clamp(32px…40px)` bottom, then a border. A 5/7 grid: copy left,
  the example thread right. Tight enough that the next section's heading sits in the first viewport at 1440×800.
  The section after the hero opens at 32px instead of the full rhythm.
- **Section rhythm:** `padding-block: clamp(44px, 5.5vw, 72px)`; section head max 62ch, 32px above its content.
- **Proportions:** pairs and splits use 5:7 (thread pairs 4:7); the hosted foot and the close use 7:5.
- **Breakpoints:** at 1080px the hero stacks (copy max 640px). At 860px wide pairs, splits, hosted foot and close go
  to one column, the values strip to 2×2, the kinds strip to one column, and wide-pair connectors hide. At 767px is
  the phone layout. At 560px the values strip is one column and hero buttons fill the row.
- **Phone (≤767px):** the top bar wraps to two rows: logo and language control first, the section links on a second
  row that bleeds to the screen edges and scrolls horizontally with no scrollbar. Each pair stacks message over
  record; connectors turn vertical (1px × 16px, dot at the bottom) and drop from the bubble to its record, right-
  aligned under outbound bubbles. Code wells stay `surface-2`. Rows wrap with the badge on its own line.
- **Static constraints:** no build step, no scripts (`script-src 'none'`), styles, fonts and images from `'self'`
  only, no inline `style`. Every interaction is CSS (`:hover`, `:focus-within`).
- **Languages:** English at `/`, Spanish at `/es/`, Portuguese at `/pt/`, plus a 404 in each. English is the source;
  es and pt carry the same markup line for line with translated text, `lang`, canonical, `hreflang` and og locale.
  The tagline and the three step strings are the owner's fixed wording in each language and are used verbatim.

### Named Rules
**The Same Markup Rule.** A structural change lands in all three languages in the same change; the pages differ only
in text and language metadata.

**The Static Page Rule.** If it needs a script, an inline style or a third-party origin, it does not ship on
watahub.dev.

## Elevation & Depth

Flat, as the inherited Overlays-Only Rule requires. Depth is tone: the chat well on `bg` reads as recessed beside the
record on `surface`, and code wells on `surface-2` recess again. The only shadow on the page is the inherited
segmented-control thumb (`0 1px 2px rgba(0,0,0,.08)`) on the current language. The top bar separates by translucency
and blur, not shadow.

## Shapes

Inherited radii: 12px for frames (threads, wide pairs, values strip, rows lists, mini frames, hosted block), 8px for
code wells, the Secret box and the skip link, 6px for buttons, nav links and the language track, 4px for language
options, 14px for bubbles and quick replies, pills for badges, circles for avatars, the unread dot, checklist marks,
feature bullets, the hero step numbers and the connector's end dot. All borders 1px. Icons are inline SVG from the panel's stroke family (16px,
stroke 1.75; 12px at 2.25 inside badges). The logo and `favicon.svg` are the panel's mark: a `text` (#18181b)
rounded square with a bright-teal (#2dd4bf) dot and ring and a light (#fafafa) arc; the favicon uses those literal
values because an SVG file cannot read the tokens.

## Components

### Message/record pair (signature)
The site's defining form. A frame (`surface`, 1px border, 12px) holds one or more pairs.
- **Message side:** `bg`, a right border, the human artifact (bubble, checklist, list) and a connector that runs to
  the column edge. Thread pairs pad 16px; wide pairs pad 24px.
- **Record side:** `surface`, a record head (12px, icon in `text-3`, mono method and path, trailing badge), then a
  code well, then optionally a note with a badge and a 13px `text-3` foot.
- **Connector:** 1px `border-strong` line with a 7px end dot, flex 24px+ (28px fixed after an outbound bubble).
- **Lit state:** hovering or focusing anywhere in a pair turns the connector and dot `accent` and gives its code wells
  and inbound bubble an `accent` border, at 0.12s.
- **Draw-in:** in the hero only, each connector scales in from its message (`scaleX`, 0.56s, inherited `--ease`,
  delays 0.25s and 0.45s); on phones the same draw runs vertically (`scaleY`). The inherited reduced-motion rule
  cuts it to 1ms, and smooth anchor scrolling is enabled only under `no-preference`.
- **Thread head:** avatar, name with a mono phone number id, and the "Example data" badge pushed right.

### Code well
`surface-2`, 8px, 10px 12px, mono 12/1.55, transparent 1px border that lights teal with its pair, scrolls
horizontally, focusable with an `aria-label`. Keys in `text-3`; the one value that matters may be set in 500.
No teal wash inside code. The closing ticket is the same well at 13px with a visible border and 16px 18px padding.

### Bubbles
Inherited bubble shapes at 14px text: inbound `surface` with a border, outbound teal aligned right, 11px time meta.
Interactive-message buttons render as a teal prompt over `surface` quick replies in `accent-ink`.

### Values strip
The four Meta values in one bordered `dl` of four cells divided by 1px borders, never four cards: label 12px
`text-3`, the value in mono 13px `text`, its description 13px `text-2`. 2×2 below 860px, one column below 560px.
The three event kinds use the same strip in three cells.

### Rows on a cell
A `surface` list with 12px corners and 1px dividers, rows 16px 20px with a 15px h3, a 14px `text-2` line and a
trailing badge. Placed inside a pair's message side the list drops its frame, fill and outer padding so it sits
directly on the well: never a card nested in a card.

### Hero steps
The owner's three steps under the lede, as an ordered list (`role="list"`): a grid with 12px gaps, max 52ch, 24px
below the lede. Each step is a row with 12px between a 22px number circle (`surface-3`, `text`, 12px, 600,
tabular, `aria-hidden`) and a 14px/1.5 `text-2` paragraph whose leading title is a block, 15px, 600, `text`. No teal.
The numbers are earned: the steps are the owner's, numbered, and their order carries meaning. The circle reuses the
checklist mark's shape. The first two step titles return verbatim as the h2s of their sections ("Connect your line"
for connect, "Deploy your agents on your line" for the agents section, nav "Agents"). The lede frames the agents as
working for a business (support, sales, bookings), and step 3 says a person can reply from the hosted Inbox, never
that they take over.

### Language control
The panel's segmented control with links for options: `surface-2` track, 2px inset, 12px options; the current page
gets `surface`, `text` and the thumb shadow via `aria-current="page"`. In the footer the same links appear as plain
13px words with the current one in `text`.

### Hosted block
Two mini frames side by side (an Inbox slice with avatars, unread dot and ellipsized previews; a Logs slice with mono
times, origin and status badges), each headed with an icon, a title and "Example data". Below, a 7:5 foot: a bulleted
features list (6px `text-3` dots, 1px dividers) and an action panel (`surface`, 12px, 20px padding) holding the
inherited **Secret** box with a sample key and its "Example data" badge, a 13px `text-3` note that keys are shown
once, a line on the courtesy credit, and a large secondary button.

### Buttons
Inherited kinds. The site adds a large size (44px, 10px 18px, 14px) for page actions: one primary per page, the rest
secondary or ghost. The top bar's GitHub link is a small secondary button.

### Badges
Inherited, with Word-and-Icon applied: ok and accent badges always carry the 12px check icon. Neutral badges carry
plain words ("Example data", "Meta", "Delivery", "API", "status").

## Do's and Don'ts

### Do:
- **Do** take every color, radius and type token from the mirrored `tokens.css`, and change them in watahub-ee, never here.
- **Do** put each human moment beside its machine record, joined by a connector, on `bg` and `surface` respectively.
- **Do** label every demo frame and every sample secret with an "Example data" badge in the page's language.
- **Do** keep code wells `surface-2` on every viewport and set every ID, path, method, header and key in mono.
- **Do** reuse the hero step titles verbatim as the h2s of their sections, in every language.
- **Do** keep the hero tight enough that the next section's heading shows at 1440×800.
- **Do** land structural changes in `/`, `/es/` and `/pt/` together.
- **Do** keep the one connector draw as the page's only animation, and leave reduced motion to the inherited rule.

### Don't:
- **Don't** edit `site/public/tokens.css` or `site/public/components.css`; copy them again from watahub-ee.
- **Don't** add scripts, inline styles, CDN fonts or third-party images; the CSP forbids them.
- **Don't** split the values or kinds into separate cards, or nest a framed list inside a pair's frame.
